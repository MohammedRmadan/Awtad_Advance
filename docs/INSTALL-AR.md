## 1. نظرة عامة

| المكوّن | التقنية |
|---|---|
| التطبيق | Node.js 22 + Express (واجهة برمجية REST + تحديث فوري SSE) |
| قاعدة البيانات | PostgreSQL 16 |
| الواجهة | عربية من اليمين لليسار + إنجليزية، خط Tajawal مستضاف محليًا |
| الدخول | اسم مستخدم وكلمة مرور يديرها مدير النظام (scrypt، قفل بعد المحاولات الخاطئة) |
| البريد (اختياري) | SMTP |
| الاستضافة | Docker Compose على خادم لينكس داخل المملكة، خلف Caddy مع HTTPS تلقائي |
| النسخ الاحتياطي | pg_dump + أرشيف المرفقات يوميًا الساعة 02:15 |

لا يعتمد النظام على أي خدمة خارجية أثناء التشغيل. الخطوط والشعار والملفات كلها تُخدَم من الخادم نفسه، والاتصال الخارجي الوحيد هو تجديد شهادة HTTPS والبريد إن فُعّل.

### الصلاحيات
| الصلاحية | ما تسمح به |
|---|---|
| مشاهد (viewer) | قراءة كل البيانات وتنزيل المرفقات والتصدير |
| محرر (editor) | + إضافة السجلات وتعديلها ورفع المرفقات |
| الإدارة (manager) | + حذف السجلات، تعديل أهداف المؤشرات، سجل النشاط، الملخص الأسبوعي |
| مدير النظام (admin) | + إضافة المستخدمين، وإعادة تعيين كلمات المرور، وفك القفل، وتعطيل الحسابات |

## 2. الإشعارات
- **داخل المنصة:** جرس الإشعارات يعرض المتأخر، والمستحق خلال 7 أيام، وما ينتهي خلال 90 يومًا، والإسناد الجديد.
- **بريد يومي:** الساعة 07:00 من الأحد إلى الخميس، لكل مستخدم بقائمة عناصره. يُعدّل التوقيت عبر `DIGEST_CRON`.
  - يصل العنصر إلى الشخص المسند إليه.
  - إن لم يُسند لشخص، يصل إلى كل من دوره في الفريق يطابق الدور المسؤول.
  - إن لم يوجد أحد، يصل إلى الإدارة.
- **ملخص أسبوعي للإدارة:** الأحد 07:30، ويعرض المؤشرات مقابل الأهداف وأهم المتأخرات.
- **بريد فوري عند الإسناد:** يصل للشخص عندما يُسند إليه عنصر.
- **تشغيل يدوي للاختبار:** `docker compose exec app node scripts/run-digest.js --weekly` (يتطلب `MAIL_MODE=smtp` لإرسال البريد`

## 3. إدارة المستخدمين
- لا يوجد تسجيل ذاتي. مدير النظام وحده يضيف المستخدمين من صفحة **المستخدمون**.
- **إضافة مستخدم:** تُولَّد كلمة مرور مؤقتة تظهر مرة واحدة، ويُجبَر المستخدم على تغييرها عند أول دخول.
- **سياسة كلمة المرور:**
  - 10 أحرف على الأقل، ويُعدّل الحد عبر `PASSWORD_MIN_LENGTH`.
  - تحتوي على حروف وأرقام.
  - لا تحتوي على اسم المستخدم.
- **القفل:** يُقفل الحساب بعد `LOGIN_MAX_ATTEMPTS` محاولة خاطئة (5 افتراضيًا) لمدة `LOGIN_LOCK_MINUTES` دقيقة (15 افتراضيًا). يفكّه المدير من الصفحة.
- **نسيان كلمة المرور:** يعيد المدير تعيينها، فتنتهي جلسات المستخدم وتظهر كلمة مؤقتة جديدة.
- **فقدان دخول كل المديرين:** من الخادم نفّذ `bdhub reset-admin`، أو `bdhub reset-admin <اسم-المستخدم>` لحساب محدد.
- **حماية مدير النظام:** لا يمكن خفض صلاحية آخر مدير نظام، ولا يمكن للمدير تعطيل حسابه بنفسه.

## 4. الإعدادات (`.env`)
| المتغير | الوظيفة |
|---|---|
| `BASE_URL` | العنوان الذي يكتبه المستخدمون، ويجب أن يطابقه حرفيًا |
| `SITE_ADDRESS` | النطاق لإصدار شهادة HTTPS تلقائيًا، أو `:80` للعمل بعنوان IP |
| `POSTGRES_PASSWORD`، `SESSION_SECRET` | أسرار يولّدها سكربت التنصيب، فلا تشاركها |
| `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD` | أول مدير نظام، ويُستخدم فقط إذا لم يوجد مدير يمكنه الدخول |
| `SESSION_HOURS` | مدة الجلسة بالساعات |
| `LOGIN_MAX_ATTEMPTS`، `LOGIN_LOCK_MINUTES`، `PASSWORD_MIN_LENGTH` | سياسة الدخول |
| `MAIL_MODE`، `SMTP_*`، `MAIL_FROM` | البريد: `none` أو `smtp` |
| `DIGEST_CRON`، `WEEKLY_CRON` | توقيت الملخص اليومي والأسبوعي |
| `MAX_UPLOAD_MB`، `BACKUP_KEEP_DAYS` | حجم المرفق الأقصى، ومدة الاحتفاظ بالنسخ |

بعد أي تعديل نفّذ `bdhub restart`.

## 5. النسخ الاحتياطي والتحديث
راجع القسم 6 من [`INSTALL-LINUX-AR.md`](INSTALL-LINUX-AR.md). باختصار:
- `bdhub backup` / `bdhub restore`.
- `bdhub update`: يحدّث التطبيق هيكل قاعدة البيانات تلقائيًا. يضيف الأعمدة والجداول الجديدة فقط، ولا يحذف بيانات.

## 6. الأمن والامتثال
- **الدخول:**
  - كلمات المرور مخزّنة بـ scrypt مع ملح عشوائي، والمقارنة بزمن ثابت.
  - رسالة الخطأ موحّدة سواء كان اسم المستخدم موجودًا أم لا.
  - قفل الحساب بعد المحاولات الخاطئة، وحد لمعدل الطلبات.
- **الجلسات:**
  - تُحفظ في قاعدة البيانات، بكوكي `HttpOnly` و`Secure` و`SameSite=Lax`.
  - تُجدَّد عند الدخول، وتُلغى عند تغيير كلمة المرور أو التعطيل.
- **حماية الطلبات:**
  - نماذج الدخول محمية برمز CSRF.
  - طلبات API تتطلب ترويسة مخصصة ومطابقة الأصل.
  - سياسة CSP صارمة بلا سكربتات خارجية، مع HSTS.
- **سلامة البيانات:**
  - قفل تفاؤلي يمنع ضياع التعديلات المتزامنة.
  - التحقق من كل حقل يتم على الخادم.
- **سجل التدقيق:** يسجل الدخول والمحاولات الفاشلة والقفل وتغيير كلمات المرور وإنشاء الحسابات، وكل إنشاء وتعديل وحذف وإرفاق، مع القيم قبل التغيير وبعده.
- **الحذف:** حذف منطقي، يبقى السجل في قاعدة البيانات ويختفي من الواجهة.
- **المرفقات:** أنواع مسموحة فقط، بحد حجم، وتُخزَّن بأسماء عشوائية خارج مجلد الويب.
- **سيادة البيانات:** قاعدة البيانات والمرفقات والنسخ الاحتياطية كلها على الخادم داخل المملكة، بما يتسق مع نظام حماية البيانات الشخصية وضوابط الهيئة الوطنية للأمن السيبراني.

## 7. بيئة التطوير
```bash
npm install
export DATABASE_URL=postgres://bdhub:bdhub@localhost:5432/bdhub SESSION_SECRET=$(openssl rand -hex 32) INITIAL_ADMIN_PASSWORD=Dev-Admin-2026
node scripts/seed.js && npm start      # http://localhost:8080  – admin / Dev-Admin-2026
```
